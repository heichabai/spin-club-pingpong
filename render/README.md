# Render 部署

这一版本保留手机 3D 球台与手势物理，并将房间服务改为普通 Node.js 服务。

- 构建：`npm ci && npm run build:render`
- 启动：`npm run start:render`
- 运行环境：Node 24.21.0，监听 `0.0.0.0:$PORT`
- 推荐：新加坡区域，Free 方案，健康检查 `/healthz`
- 房间为临时会话，服务休眠、重启或重新部署后需重新建房。
- 只部署一个实例；联机优先 WebRTC，不通时使用同源 WebSocket 实时中继；HTTP 保留用于房间管理及断线恢复。
- Free 服务闲置可能休眠，首次访问需等待唤醒；正式比赛的延迟与手机可达性仍需实机验证。

当前服务使用公开仓库 URL，主分支更新后需手动触发 Render 部署；连接 GitHub 集成后可启用自动部署。不要上传 node_modules、.env、.git、.wrangler 或 .openai 本地信息。

## 验证

`node --test tests/*.test.mjs`

`node render/test-api.mjs`

启动服务后运行 `node render/test-live.mjs`，验证实时双向传输、可靠命令确认、断线重连和凭据撤销。

手势输入记录未裁剪的手指轨迹，实际球拍位置限制在可达区；用最近 45ms 的轨迹估计击球速度和加速度。自动高度变化不会改变触摸投影平面。上划、下划、横擦通过接触摩擦产生真实角速度，飞行和台面反弹均使用该角速度。

发球准备期间，上搓发上旋、下搓发下旋，搓动达到手势阈值立即出球，无需松手；本次搓动方向决定旋转，速度决定旋转强度，点击不发球。人的发球回合等待手动操作，AI 回合自动发球。联机发球命令携带本次手势，主机按发球方视角转换旋转轴，并检查发球权。

这是独立实现；原作内部参数未公开，不能宣称与《虚拟乒乓球》完全相同。

球拍可达范围扩展到球台两侧及底线后方，主客场使用同一范围。回球速度上限为 12.5 m/s，手势向前力量略降；增强旋转升力和台面摩擦，让旋转的飞行及反弹差异更明显。


本次合并更新：鼠标自由上下移动即可发球（不要求按键），手机仍以手指搓动发球，短距离手势也可触发。整段球的飞行时钟为原来的 0.56，保留旋转弧线与反弹关系，球拍响应不降速；主机和客机采用同一时钟。

联机保留 WebRTC、认证 WebSocket 及 HTTP 恢复。客机每个显示帧仅计算一次预测，短暂缺包最多预测 180ms；击球拍面辅助从 25 个完整球路试算改为 9 个粗选加至多 4 个细选。拥堵时传输层跳过旧位置，中继合并尚未处理的位置包；发球、暂停、重开仍逐条可靠确认。实时数据也更新连接健康状态，避免仅 HTTP 心跳失败就暂停仍在通信的对局。

回归涵盖自由鼠标发球、手机手势、双方发球权、扩大可达范围、旋转飞行/反弹、降速、拥堵位置更新、命令顺序/去重、断线恢复和凭据撤销。自动测试不能代替手机跨运营商实测；主机裁决模型仍受真实网络往返时间影响。


回合节奏：初次准备、重开及擦网重发均有 1000ms 发球保护。出界、下网或二次落台判分后，原球保留实际速度、旋转及高度，继续飞落/反弹 550ms，然后摆出下一颗发球并保留 1000ms 保护；取消原来的 1500ms 隐藏球空等。收尾不再检查球拍或重复判分，客机也预测同一颗收尾球。期间球拍可正常移动，手势不缓存、不自动补发；保护结束需新的搓动，持续按住的手指也可重新搓动，无需点击按钮。AI 同样遵守节奏。主机检查所有发球入口；快照发送剩余毫秒数供客机同步，不依赖两台设备时钟一致。

旋转手感：只把手势产生的角速度贡献增强至 2.1 倍，静止挡球对来球旋转的响应保持不变；发球旋转范围约 75–500 rad/s。飞行 Magnus 力和台面摩擦仍使用真实角速度，增强旋转可改变弧线及反弹，不增加向前力量。整段飞行时钟从上一版 0.72 降为 0.56（再慢约 22%），双方一致，球拍响应不降速。回归增加短收尾持续移动/只计一次分、客机收尾预测、强旋弯曲/反弹、静止挡球以及两端多档旋转发球合法性。
